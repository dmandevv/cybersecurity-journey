# 1.2 — Summarize fundamental security concepts.

**Domain 1 — General Security Concepts** · 12% of the exam · **36 terms** from the official objectives.

Every term below is quoted from the SY0-701 objectives document, version 7.0. Tick a box once the term can be explained without looking, and write the explanation underneath it.

- [x] **Confidentiality, Integrity, and Availability (CIA)**
  - **Confidentiality:** who can read the resource. **Integrity:** has the resource been tampered with. **Availability:** can the resource be accessed when needed.
  - *Examples:* sniffed Wi-Fi password → C; switch config edited to send logs to the wrong collector → I (also A for the real collector — pick what the question stresses); `nic0` hang takes every VM dark → A.
  - *Refinement:* integrity covers **preventing** unauthorized change as well as detecting it (hashing detects; access control and signing prevent). Ransomware encrypting files = **A**; double extortion (steal then encrypt) adds **C**.
- [x] **Non-repudiation**
  - Evidence that you and only you could have done something. **Example:** my git commits show `%G? = N` — unsigned, so the author name is just a claim anyone can set. Fix: SSH key added to GitHub **as a Signing Key**, then `gpg.format ssh`, `user.signingkey`, `commit.gpgsign true`.
  - *Refinement:* needs something **only one party holds** — a private key, not a shared password (either holder could deny it). Digital signature = integrity + non-repudiation. Shared admin accounts break it: config-change alerts only prove *who* if every admin has their own login.
